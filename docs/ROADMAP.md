# Execution Roadmap and Hard Gates

## Phase 0 — Read-only discovery (mandatory)
Verify exact repo, actual files, existing readme/instructions, branch, source code, package manager, architecture, UI, deployment and integrations. Report file map, actual stack and risks. A documentation plan does not prove implementation.

## Phase 1 — High-fidelity mockups and STOP
Create public homepage/service/form desktop + mobile (1440/390px), Arabic RTL previews, Russian typography, admin overview/editor in desktop + mobile and error/empty/loading states. Present visually with rationale and **STOP for explicit approval before any UI implementation**. General plan/document approval does not count.

## Phase 2 — Confirm factual content & technical decisions
Confirm services now available, approved language pairs, education/experience wording, professional contact, assets/rights and actual booking method. Choose minimum architecture and log decision; confirm costs/risks. Block unsupported public claims.

## Phase 3 — Public UX after approval
Implement design system, accessible navigation, hero, service pages, real biography, 3-language routes and responsive/RTL layouts in the actual verified stack.

## Phase 4 — Media and video
Integrate approved portraits/logo, prominent on-demand Vimeo with hash, poster, fallback/transcript, editable admin reference.

## Phase 5 — Admin and content publishing
Implement structured content, revisioned 3-locale drafts, review queue, safe preview/publish/rollback, settings, services/media and owner authentication.

## Phase 6 — Enquiries and notifications
Build validated conditional forms, persistent references, admin inbox, auditable statuses, anti-spam and provider-failure tolerance. Respect Preply restrictions.

## Phase 7 — Localization, SEO, quality
Finish human-reviewed EN/AR/RU content, proper RTL, hreflang/canonical/sitemap, accessible video and forms, performance/usage optimization.

## Phase 8 — Recovery rehearsal and release checks
Test in staging with synthetic data: auth, forms, migrations, rollback, provider outage, database/cost boundaries and full browser matrix. Fix regressions. Prepare proof of tests and no PII leak.

## Phase 9 — High-risk production approval and deployment
**Stop** for first production launch, external account/DNS changes, costs or irreversible mutations. Deploy only after authorization. Verify live website, admin, video and lead delivery; document rollback.

## Phase 10 — Handover
Record actual architecture, runtime instructions, costs, backups, owners and admin guide. Produce concise verification evidence and unresolved items. Do not silently start deferred features.

## Required outputs
Per phase: changed-file map, decisions, tests/metrics, edge cases, blockers and exit criteria. Routine actions after approval are autonomous; design and high-risk checkpoints are not optional.

## Acceptance
Beautiful, accurate personal professional site; exact 3 public locales; robust Vimeo fallback; truthful service claims; admin control, reliable enquiries and recovery; WCAG 2.2 AA target; low resource usage. No Korean.
